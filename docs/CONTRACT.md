# The Contract

Every script, workflow, prompt, and skill in this kit agrees on the conventions in this
file. This exists because the reference implementation learned the hard way that two
tools with slightly different definitions of the same thing (a "primary source", a
"section", a "published week") will each be internally consistent and still disagree —
and a metric two tools define differently cannot be trended.

If you change anything here, grep the repo for the thing you changed. Nothing may
redefine it locally.

## 2. `site.config.json`

Single source of truth for identity. Every script that needs a name, color, ZIP, or
address reads this file — no script hardcodes any of them.

```json
{
  "zip": "00000",
  "siteName": "00000 News",
  "experimental": true,
  "tagline": "A weekly brief for ZIP code 00000",
  "city": "Anytown",
  "state": "ST",
  "timezone": "America/New_York",
  "domain": "",
  "workerName": "zipcode-news-00000",
  "contactEmail": "",
  "publishDay": "Friday",
  "cronUtc": "0 20 * * 5",
  "volume": 1,
  "colors": { "accent": "#7a2e2e", "paper": "#fbfaf7", "ink": "#1a1a1a" },
  "sections": [
    "The Week in One Page",
    "Local Government",
    "Development & Land Use",
    "Transit & Getting Around",
    "Schools & Youth",
    "Public Safety",
    "Real Estate & Market Trends",
    "Dining & Retail",
    "Around the Neighborhood",
    "Parks & Recreation",
    "Mark Your Calendar"
  ],
  "geographyNote": ""
}
```

Rules:
- `experimental: true` appends "(Experimental)" to the masthead everywhere the name
  appears. It becomes *eligible* for removal only by the accuracy-log criterion
  (8 consecutive issues, no wrong claim, ≤1 misleading each), never by preference —
  and even then, **no agent or automated process flips it**. When the bar is met,
  propose the change to the publisher with the evidence; edit `experimental` only
  on their explicit approval.
- `domain: ""` means the site serves from `<workerName>.<account>.workers.dev` (free).
  Setting a domain changes only links/canonical URLs — deploy mechanics are identical.
- `contactEmail: ""` means the issue carries no contact route and the gates do not
  require one. A non-empty value must be a mailbox a human (or supervised agent) reads.
- `geographyNote` is the local equivalent of "police districts ≠ ZIP boundaries" —
  whatever mismatch exists between your data geographies and your ZIP. Empty until
  /find-sources fills it in; the verify gate warns while it is empty.
- `sections` is the standing section list. A quiet week is a short section that says
  so — never a removed section. verify-issue warns on any standing section missing.
- Derived, never stored: issue number = 1 + count of prior files in `issues/`.

## 3. `config/sources.json`

The single definition of source classes. `bin/source-classes.mjs` is its ONLY reader;
every other tool imports from source-classes, never from the JSON directly.

```json
{
  "self": ["example.workers.dev"],
  "primary": [],
  "interestedPrimary": [],
  "secondary": [],
  "noVintage": [],
  "officialIncident": [],
  "adjacentJurisdictions": []
}
```

- `primary`: agency/record hosts — the record itself (courts, police data portals,
  recorder of deeds, open-data portals, school district).
- `interestedPrimary`: authoritative for what they themselves said/did, AND an
  interested party (neighborhood associations, advocacy groups, chambers of commerce).
  Reported separately; NEVER counted toward primary share.
- `secondary`: news outlets, aggregators, commercial estimate sites.
- `noVintage`: hosts that silently revise (e.g. real-estate estimate sites) — citing
  one without a snapshot in the facts file draws a warning.
- `officialIncident`: hosts that satisfy the Tier-A requirement for
  death/violence claims.
- Self-links are excluded from every share denominator.
- An unrecognized host is `unclassified` — a new source worth a look, not an error.
- Host matching is by suffix (`sub.example.gov` matches `example.gov`), on EVERY
  http(s) URL in the text (this publication prints citations as visible text, so
  scanning only `href=` undercounts).

## 4. `config/privacy.json`

Patterns the privacy gate (bin/privacy-scan.mjs) blocks. Populated by /setup with the
publisher's own identity; extended whenever a scare happens.

```json
{
  "publisherNames": [],
  "blockedEmails": [],
  "allowedEmails": [],
  "streetMarkers": [],
  "coordinatePrefixes": [],
  "extraPatterns": [ { "pattern": "", "flags": "i", "why": "" } ],
  "finestGeography": "ZIP"
}
```

Built-in generic checks (always on, regardless of config): decimal lat/lon pairs
("a coordinate is an address that hides from a name-based search"), second-person
home framing (`your house/home/block/street/door`), and house-number + street-name
shapes listed in `streetMarkers`. `coordinatePrefixes` (e.g. `{"lat":"38.9","lon":"-77.0"}`)
tightens the coordinate check to the local area. Every entry carries a `why`.

## 5. Issue HTML contract

Issues in `issues/` are BARE: no `<html>`/`<head>`, no site nav, no footer.
`build.mjs` injects chrome (`<style id="site-chrome">`, `.sitenav`, `.issuebar`,
`.sitefoot`, canonical/OG/RSS/generator meta). An issue containing `sitenav`,
`issuebar`, `sitefoot`, or `site-chrome` is double-wrapped → FATAL in verify.

Required structure (class names are load-bearing — verify-issue, measure-issue,
build.mjs, and the RSS/archive generators all key on them):

| Element | Meaning |
|---|---|
| `<div class="aibar">` | Top-of-issue AI-disclosure box; must contain the exact phrase "not reviewed by a human editor" |
| `<section class="frontpage">` | Page one |
| `<div class="fp-item">` … `<div class="fp-rank">N</div>` + `<p class="fp-h"><b>…</b></p>` | Ranked front-page items (3–6). `fp-h` headlines are reused verbatim for the archive listing and RSS item descriptions |
| `<div class="fp-box">` | Front-page panels ("The numbers", "On the calendar") |
| `<h2 class="sec">` | Section heading — sectionsOf() splits on THIS, not on `<section>` |
| `<sup class="cite"><a href="#sN-n">n</a></sup>` | Inline citation |
| "Sources for this section" + `<ol class="srclist">` | Per-section source block; URLs as visible text in `<span class="u">` ("a hyperlink is dead on paper") |
| "About This Brief" section | Method, limitations, disclaimers, corrections route |
| `Why it matters:` | Inline clause on front-page items (plain text, no callout boxes) |

Anti-patterns (FATAL in verify): `.why` callout boxes; CSS outside `<style>`;
site chrome present; a `fp-item` without rank or bold headline.

The four non-negotiables, enforced by gates, not by promises:
1. No reader-identifying information (privacy-scan).
2. AI disclosure everywhere a reader can arrive: aibar, About section, PDF footer,
   PDF metadata, RSS generator + item prefixes, HTML `<meta name="generator">`.
3. Per-section attribution with visible URLs and query dates.
4. Failed fetches admitted in reader-facing prose — if `facts.errors[]` is non-empty
   and the issue never admits a gap, that is the exact shape of a fabricated number
   → FATAL.

## 6. Facts file contract (`data/facts/YYYY-MM-DD.json`)

Written only by `bin/fetch-data.mjs` (which calls the adapters in `bin/adapters/`).

```json
{
  "week": "YYYY-MM-DD",
  "queriedAt": "ISO-8601",
  "zip": "00000",
  "errors": [ { "source": "", "url": "", "message": "" } ],
  "notes": [],
  "agentRules": [],
  "<domain blocks per adapter>": {}
}
```

Rules:
- **Every value is null unless actually retrieved.** A failed fetch goes to `errors[]`
  with the failing URL. Null is an honest answer; a guessed value is not.
- `agentRules[]` carries instructions embedded in the data itself (small-base notes,
  "report the absolute change, not the percentage", geography caveats). The writing
  model must obey them.
- An empty result from a working query (e.g. zero open dockets) is a **verified
  answer**, not a gap — adapters distinguish "queried, empty" from "failed".
- Adapters assert MEANING, not status codes: field exists, ZIP is present, count is
  plausible. A 200 with zero rows where rows are expected is a failure, because in
  print it becomes "nothing happened", which is a lie rather than a gap.

## 7. Script CLIs (all Node ≥ 20, ESM, zero runtime deps; playwright is the only devDependency)

| Script | Invocation | Exit |
|---|---|---|
| `build.mjs` | `node build.mjs` | 0 = public/ written |
| `bin/fetch-data.mjs` | `--week YYYY-MM-DD` | non-zero only on total wipeout |
| `bin/verify-issue.mjs` | `--week YYYY-MM-DD` | 1 on any FATAL |
| `bin/privacy-scan.mjs` | `<file...>` | 1 on any hit |
| `bin/normalize-issue.mjs` | `<file>` (in place, idempotent, BEFORE pdf+build) | |
| `bin/html-to-pdf.mjs` | `<in.html> <out.pdf> "<footer text>"` | |
| `bin/measure-issue.mjs` → lives at `QA-QC/measure-issue.mjs` | `<issue.html>` | 2 if source-classes import fails |
| `bin/check-published.mjs` | (no args; computes last publish day) | 1 on FATAL |
| `bin/smoke-test.mjs` | `--base URL [--week W]` | 1 on failure |
| `bin/probe-sources.mjs` | `[--json]` | 1 on critical failure |
| `bin/build-addendum.mjs` | `--week W` | writes addendum + GITHUB_OUTPUT high/total |
| `bin/source-retrospective.mjs` | `--min-age-days N [--write]` | |
| `bin/doctor.mjs` | (no args) | 1 if any gate mis-fires on fixtures |

Shared conventions for every script:
- Loads config via `bin/lib/config.mjs` (`loadConfig()`, `loadSources()`, `loadPrivacy()`).
- Prints something unconditionally — **silence is not success**.
- Uses `fileURLToPath(import.meta.url)`, never `import.meta.url.pathname` (paths
  with spaces).
- Gates exit non-zero BEFORE anything is committed or published.
- Every FATAL/WARN message says what to do about it, not just what is wrong.

## 8. Pipeline order (weekly)

fetch → write (the ONLY model step) → issue-exists guard → privacy-scan (GATE) →
verify-issue (GATE) → normalize → PDF → build → addendum → build-smoke →
upload artifacts → QA-QC-unchanged guard → commit (the commit IS the deploy trigger).

Cloudflare Workers Builds watches `main`: build command `node build.mjs`, deploy
command `npx wrangler deploy`, serving `./public` as static assets. GitHub holds no
Cloudflare credential; Cloudflare holds no model credential. The repo is the handoff.

## 9. QA/QC separation

Four layers, deliberately unmerged — **no weighted composite score, ever**
(averaging is the wrong operation when some failures are disqualifying):

1. **Gates** (verify, privacy): binary, block publication.
2. **Rubric** (QA-QC/RUBRIC.md, seven questions): graded craft review; verdict rule =
   publishable if no question Weak AND Q1 + Q7 Strong.
3. **Accuracy log**: are the claims true (3 claims/issue, post-publication).
4. **Readers**: is it useful.

The writing model may read QA-QC/ and never write to it — enforced by a workflow
guard (`git status --porcelain QA-QC Research` must be empty), not by a promise.
The writing model never scores its own output.
